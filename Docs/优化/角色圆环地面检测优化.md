# 我做的优化：减少静止角色圆环的地面检测

日期：2026-11-17

## 问题

我在角色脚底圆环中使用向下射线获取地面位置和法线。原来每个显示圆环的角色每帧都会检测一次，即使角色站在固定地面上完全不动，也会重复查询相同的结果。

例如在 60 FPS 下，一个静止角色每秒约检测 60 次。这个数字只是查询次数，不代表已经测得具体 CPU 耗时；角色数量增加后，这些重复查询值得减少。

## 我的解法

我保留组件每帧 Tick，只降低满足条件时的地面检测频率：

| 情况 | 检测方式 |
| --- | --- |
| 首次显示、没有有效地面缓存 | 立即检测 |
| 角色移动，包括坡道、上下台阶、位置修正和传送 | 每帧检测 |
| 静止在 Static 固定地面上 | 默认每 0.2 秒检测一次 |
| 脚下组件为 Movable / Stationary、模拟物理，或角色绑定了可移动基座 | 每帧检测 |
| 缓存地面被销毁、变换变化、角色处于下落状态 | 立即检测 |

这里的“静止”同时检查实际脚底位置和速度，不只看输入或移动速度。这样角色被平台带动、网络位置修正时，也不会因为没有移动输入而错误地停更。

对于平台，我采用保守策略：只要地面组件不是 Static，就不降低检测频率；即使平台暂时停止，仍然每帧检测。新引擎的非 PrimitiveComponent 移动基座也不进入静止缓存路径。

## 简单代码

下面是思路示例，省略了地面有效性、阵营和材质检查；项目完整实现在 `FactionRingComponent.cpp`。

```cpp
TimeSinceGroundTrace += DeltaTime;

const bool bStationary =
    Feet.Equals(LastTracedFeet, 0.01f) &&
    Character->GetVelocity().IsNearlyZero() &&
    !Character->GetCharacterMovement()->IsFalling();

// bFixedGround 还要检查地面弱引用、Mobility、物理模拟、
// 地面变换，以及角色当前的移动基座。
if (IsVisible() && bFixedGround && bStationary &&
    TimeSinceGroundTrace < StationaryTraceInterval)
{
    return; // 保留上次贴花位置与方向，不再发射重复射线
}

TimeSinceGroundTrace = 0.f;
LastTracedFeet = Feet;

// 执行原来的地面射线，缓存命中组件和它的变换。
// 使用命中位置和法线更新圆环；未命中则隐藏并清除缓存。
```

`CachedGround` 使用弱引用，不延长地面组件生命周期。地面被销毁后，缓存自动失效，下次更新重新检测。

材质参数更新在提前返回之前执行，选中状态变化也有独立入口。因此静止时选中、取消选中或阵营变化仍能及时改变颜色和亮度，不需要等待 0.2 秒。角色死亡或隐藏的检查同样在检测节流之前执行。

## 为什么不直接关闭 Tick

圆环使用绝对世界坐标，不能依赖父组件自动带动它。如果直接关闭 Tick，角色开始移动后可能来不及恢复地面检测，圆环会停在旧位置。只跳过重复的射线查询，可以保留原有移动响应和材质更新。

## 参数和适用边界

- 在角色蓝图的 FactionRing 组件中调整 `Stationary Trace Interval`，默认 0.2 秒；设置为 0 可恢复每帧检测。
- 0.01 cm 是脚底位置比较的容差，相对于上次实际检测的位置累计比较，不会持续忽略缓慢移动。
- 缓存期间已有地面的变换改变会立刻触发检测。固定地面上突然出现新的障碍物或只改变碰撞/几何但不改变组件变换，可能等到下次周期检测，默认最长约 0.2 秒再加帧调度时间。
- 没有命中有效地面时继续每帧检测，优先保证圆环能及时重新出现。
- 这次优化不改变射线通道、复杂碰撞设置、投射深度和坡面法线算法，也不增加网络同步。

## 验证方式

我扩展了 `BoldersDemo.Presentation.FactionRing` 自动化测试，直接统计真实射线调用次数：静止固定地面、逐帧小幅移动、静止可移动平台，并检查台阶升降和平台移动/旋转时的实际贴花位置、方向。计数器只在开发自动化测试配置中存在。

同时保留原有颜色、选中/取消、死亡、高台、斜坡和无地面测试，并运行怪物描边回归测试。测试结果见本次验证记录；查询次数的下降不能直接当作整体帧率或 CPU 耗时提升比例。
